# 互动营销灵感库

https://funkja2413.github.io/insprationMC/

静态案例库：`index.html` 展示 `data/cases.json`，`images/` 保存案例图片。网站的「不感兴趣」心碎按钮沿用原有隐藏逻辑，将排除记录写入 `data/removed.json`，确认后有 5 秒撤销时间；发布时必须保留它，已排除的案例不能重新加入。

卡片标题下的「玩法 × 品牌类型」由 `presentation.js` 的共用规则根据现有案例内容生成，辅助快速比较案例，也支持关键词搜索。核验说明 `availability_zh` 保留在原始数据中，不在卡片上显示。体验链接使用游戏手柄图标；多个真实体验入口仍收纳在同一个按钮中。摘要规则测试：`node --test tests/presentation.test.cjs`。

## 搜索与筛选

顶部只保留「全部案例／我喜欢的case」两个视图。桌面使用玩法、行业下拉框；「更多筛选」包含手机可玩与实机演示。手机端统一放入「筛选」底部面板，修改后点击「查看」才生效，关闭或按 Escape 会取消未应用的选择。已选条件可逐项移除或清空，清空筛选保留搜索词。

`filters.js` 根据已有摘要归并为 8 类玩法、12 类行业，多个维度取交集。卡片不再显示细碎标签，但 `tags` 原始数据仍完整保留并参与关键词搜索。手机可玩仍仅匹配 `mobile: "yes"`，实机演示仍要求真实 HTTP(S) 演示入口且排除 `demo_type: "puzzle_source"`。分类与组合测试：`node --test tests/filters.test.cjs`。

## 收藏

每张卡片可点击「收藏／已收藏」，在「我喜欢的case」标签页查看收藏；搜索和筛选在两个视图中都可用。收藏使用稳定的 case ID，并立即保存到当前浏览器的 localStorage，刷新后仍保留。无 GitHub 授权时无需登录即可收藏，页面会明确显示仅在本浏览器保存；浏览器禁用存储时会显示刷新可能丢失的提醒。

若当前浏览器已保存原有 GitHub 写入授权，会复用同一授权同步 `data/favorites.json`，无需创建新凭据或扩大权限。这个文件是 ID 数组，与此公开案例库一起共享，其他设备可读取已同步的收藏。离线或授权失效时继续本地保存，联网后或点击「重试收藏同步」再尝试；不会为收藏自动打开令牌弹窗。

同步前读取最新文件及 SHA，只合并本机待处理的收藏／取消操作；冲突时重读再合并。不同案例的收藏不会互相覆盖，同一案例以最后成功同步的操作为准。同步过程中继续操作，会按操作版本保留后续变更。同浏览器其他标签页的收藏变化会通过 storage 事件更新。

删除的案例在全部与收藏视图中同时隐藏，收藏数也不计入它；删除不抹去收藏标记，因此在撤销时会恢复原收藏状态。发布时应保留 `data/favorites.json`，不以空文件覆盖用户已有收藏。

同步逻辑回归测试：`node --test tests/favorites.test.cjs`（无需额外依赖）。浏览器测试 `tests/browser.cjs` 使用 Playwright 与独立临时 Chrome，会模拟 GitHub API，不使用真实凭据或提交删除；先启动本机静态服务器，默认地址为 `http://127.0.0.1:8766`，可通过 `TEST_BASE_URL` 指定。

## 追加案例

使用 Python 3，无需安装依赖。开始前确认工作区干净，并同步最新 `main`，以免覆盖用户刚刚删除的记录或其他更新：

```bash
git switch main
git pull --ff-only origin main
python3 publish.py --check
```

先核实官方或制作方来源，将真实案例图片保存到 `images/`，并在批次记录或提交说明中注明图片来源。不要用合成图冒充项目实机画面。新批次可放在仓库外，格式为案例数组，或 `{"cases": [...]}`。

每条案例保留以下必需字段：`id`、`title_zh`、`brand`、`agency`、`region`、`format`、`date`、`why_zh`、`style_zh`、`live_url`、`source_url`、`image`、`mobile`、`tags`。`tags` 是字符串数组，其余必需字段是字符串。`id` 必须唯一、稳定；`image` 推荐使用 `images/案例名.webp` 等本地相对路径。日期按来源支持的精度填写，未知时可留空，不推测日期或当前可玩状态。

可选兼容字段：

- `demo_url`：真实实机演示视频、动图或演示页面，单独展示为「实机演示」，不要放进试玩入口；动图和未完整播放等核验范围应在 `availability_zh` 中说明。
- `demo_label`：演示按钮的可选标签，默认「实机演示」。原广告等谜题素材可标为「谜题原片」，同时设置 `demo_type: "puzzle_source"`，避免进入「实机演示」筛选。
- `availability_zh`：核验事实，例如「活动已结束」「入口可访问，未完整试玩」「原试玩返回 403」。
- `live_label`：体验链接的准确标签；没有完成试玩核验时可写「活动入口」，不应暗示已经确认可玩。
- `mobile: "historical"`：历史手机互动案例；用于活动已结束或当前可玩性未确认的项目。`mobile: "yes"` 应有当前手机试玩依据。旧字段值与已有案例继续保留。

```bash
python3 publish.py /path/new-cases.json --date YYYY-MM-DD
python3 publish.py --check
git diff --stat
git diff -- data/cases.json data/removed.json
```

将 `YYYY-MM-DD` 替换为实际库更新日期；它只更新文件顶层 `updated`，不会更改各案例的 `date`。脚本按批次顺序前置新增案例，保留所有已有案例对象、顺序及其他顶层字段。相同 `id` 且内容完全相同会跳过；相同 `id` 但内容不同会报错，整批不写入。排除清单中的 `id` 会跳过。没有新增时不会改写数据文件，重复运行不会制造重复案例。脚本永不改写 `data/removed.json`。

`--check` 仅检查：案例条数与 `count` 一致、必需字段及类型、唯一 `id`、本地图片存在，以及案例未命中排除清单。它不会联网核实链接、图片内容或可玩性；历史 `live_url` 中的非 URL 文本仍可保留。提交前另行检查图片清晰度、入口和演示视频，确认案例卡片、筛选和删除功能正常。

## 发布与核验

脚本只准备数据，不提交、不推送、不处理凭据，也不创建自动任务。确认变更后，使用本机已配置的 GitHub 访问方式提交到 `main` 并推送。若远端在此期间有更新，先同步并重新检查排除清单和数据，不要强制推送或覆盖远端删除记录。

推送后在 GitHub Actions / Pages 中确认对应提交的部署成功，再打开[线上案例库](https://funkja2413.github.io/insprationMC/)核验新增条数、图片、实机演示和体验入口，并确认已删除案例仍然隐藏。仅提交或推送成功，不代表 Pages 已完成部署。
